# Переработка навигации, Files, My Changes и Streams

Статус: реализовано и проверено 22 июля 2026 года. Документ создан до изменения кода и сохранён как контракт реализации и приёмки.

## 1. Цель

Сделать ежедневные операции с файлами и changelist заметнее, сократить постоянную ширину навигации и добавить безопасный stream workflow. Интерфейс должен показывать реальные данные Helix Core; кнопки без работающего пути `UI → Rust → p4 → refresh` не добавляются.

## 2. Каркас и навигация

Левая панель имеет три состояния:

1. **Компактная** — состояние по умолчанию: видны только иконки пунктов, названия доступны через tooltip и accessibility label.
2. **Раскрытая** — видны иконки и названия; ширина основного content area уменьшается без перекрытия.
3. **Скрытая** — панель убрана, но в header остаётся доступная с клавиатуры кнопка её возврата.

Пользователь циклически переключает состояния явными кнопками. Выбранный пункт различим не только цветом. Навигация сгруппирована так:

- Files;
- My Changes;
- Streams;
- визуальный разделитель;
- Shelves;
- Jobs.

History, Depot и Labels перестают быть самостоятельными пунктами, но их рабочие сценарии не удаляются: история и depot browser входят в Files, а labels остаются доступны через Global Go To/command palette до отдельного продуктового решения.

## 3. Files

### 3.1 Общий экран

Files — единая точка работы с workspace и depot. В верхней части находится переключатель источника:

- **Local files** — mapped workspace files, локальное состояние и локальные действия;
- **Depot files** — дерево depot и read-only/server actions.

Экран сохраняет общий layout `toolbar → tree | inspector`. Выбор файла или папки обновляет инспектор справа без перехода на отдельный экран и без layout jump.

Уточнение после UX-проверки: экран не начинается с обязательных или необъяснённых строк поиска. При входе Local files сразу показывает кеш корневого каталога и перечитывает только один уровень авторизованного client root. Вложенный каталог загружается при первом раскрытии: кеш появляется сразу, рядом показывается spinner, а точное disk-содержимое и нерекурсивный Perforce status обновляются в фоне. Отображаются и пустые папки; у ещё не загруженной папки вместо ложного нулевого file count показывается многоточие. Состав Local Files определяется только фактическими файлами на диске; отсутствующие локально server records в дерево не добавляются. Перед `p4 fstat //client/path/*` приложение сравнивает fingerprint последнего submitted changelist, pending changelists и opened-файлов workspace; при неизменном fingerprint каталог остаётся на cached status. Тяжёлый `p4 reconcile -n` запускается только явным действием Reconcile. Scope, текстовый поиск, status filter и смена tree/list являются дополнительными настройками в сворачиваемом блоке с labels, placeholders и короткими подсказками.

Local Files сохраняет текущее дерево и незавершённый directory request при переходе в другой раздел или на Depot Files. Возврат не создаёт параллельную загрузку. Явный Refresh обновляет только каталоги, которые пользователь уже раскрывал в текущей сессии.

### 3.2 Local files

- Основное представление — file tree с раскрываемыми каталогами и файлами.
- Дерево показывает папки и все найденные в выбранном bounded scope файлы: tracked, opened, outdated, unresolved, locked/other-open, unmapped, untracked и ignored, когда эти состояния возвращены сервером/preview.
- Каждый файл имеет обычную file-type icon и отдельный status marker/label. Статус нельзя кодировать только цветом.
- Hover/focus tooltip показывает полный путь, статус, размер и changelist; отсутствующие данные явно обозначаются.
- Игнорируемые файлы и каталоги показываются приглушённым оранжевым цветом, но остаются читаемыми.
- Выбор файла показывает его bounded revision history справа. Выбор папки показывает bounded submitted history по scope этой папки.
- Multi-select сохраняет click, Ctrl/Cmd-click и Shift-click там, где доступны batch actions.

Доступные действия над локальными файлами:

- получить новые версии выбранных файлов через server-backed sync preview и существующий Operations Center;
- открыть для изменения (`p4 edit`);
- добавить (`p4 add`);
- добавить правило в ignore без потери файла;
- пометить на удаление (`p4 delete`);
- отменить локальные изменения (`p4 revert`) с preview и подтверждением;
- удалить только локально с отдельным destructive confirmation.

Пункты скрываются или disabled с понятной причиной, если состояние файла не допускает действие. Mutation выполняется над точными depot/local identifiers и заканчивается refresh дерева и инспектора.

### 3.3 Depot files

- Depot отображается другим спокойным цветовым акцентом и явной меткой источника.
- Дерево загружается лениво и bounded, без глобального `//...` scan.
- Выбор файла/папки показывает историю справа так же, как в local mode.
- Действия, требующие существующего local path или opened state, для depot-only элементов не показываются.
- Видимая кнопка получает новую версию только для mapped/доступного scope через preview sync.
- Локальные файлы, отсутствующие в текущем depot view, остаются в дереве серыми и неактивными, чтобы переключение источника не создавало ложное впечатление потери данных.

## 4. My Changes: Unactual

Экран сохраняет всю текущую функциональность changelist, opened files, shelves, submit, revert и drag-and-drop.

Добавляется косметическая локальная классификация changelist:

- через контекстное меню numbered pending changelist переносится в **Unactual**;
- тот же перенос в обе стороны доступен drag-and-drop строки между актуальным списком и секцией Unactual;
- нижняя секция Unactual сворачивается и раскрывается независимо;
- archived changelist остаётся обычным server changelist: его можно выбрать, редактировать, наполнять, shelve, revert и submit без ограничений;
- через контекстное меню он возвращается в актуальный список;
- Default changelist не архивируется;
- признак хранится локально отдельно для server/user/workspace и автоматически очищается для changelist, которых больше нет после refresh.

Это представление не изменяет Perforce server state и не переименовывает changelist.

## 5. Streams

### 5.1 Представление

Streams состоит из двух постоянных panes:

- слева — bounded дерево streams с parent/child связями;
- справа — граф только включённых streams, показывающий отношение parent/child и stream type через подпись/форму, а не как Git commit DAG.

У каждого stream есть переключатель видимости на графе. Выбор в дереве и графе синхронизирован. Текущий stream workspace отмечен текстом и отдельной заливкой/рамкой. SVG не растягивает узлы больше заданного органичного размера, когда на графе мало элементов.

Дерево поддерживает Ctrl/Cmd-toggle и Shift-range multi-select. Команды `Показать выбранные` / `Скрыть выбранные` находятся в верхней панели и действуют на текущую selection, а `Показать все` / `Скрыть все` — на весь каталог. Checkbox выбранного stream применяет действие ко всей multi-selection. Выключение родителя скрывает всё его поддерево, но включение родителя включает только его самого. Для явного показа или скрытия всех потомков существуют отдельные команды в context menu; смешанное состояние детей показывается indeterminate checkbox. Каждая ветка с детьми независимо сворачивается и раскрывается caret-кнопкой без изменения графа.

Streams поддерживает ту же локальную косметическую секцию **Unactual**:

- ПКМ переносит stream в сворачиваемую нижнюю секцию;
- ПКМ возвращает его в актуальное дерево;
- drag-and-drop переносит один stream или выбранную группу из одной секции в другую;
- перенос родителя в Unactual переносит всё его поддерево, а возврат родителя возвращает только его самого; context menu содержит явные команды для переноса/возврата всех потомков;
- stream остаётся доступен для просмотра и переключения;
- состояние хранится отдельно для server/user/workspace и очищается для исчезнувших stream paths.

### 5.2 Переключение stream

Переключение запускается двойным левым кликом либо пунктом контекстного меню. Перед mutation всегда открывается общий dialog, который показывает source stream, target stream и две независимые стратегии:

**Локальные opened-файлы**

- `Shelve` — сначала сохранить локальные opened-файлы в server shelf; Default changelist требует безопасного numbered changelist workflow либо блокирует вариант с объяснением;
- `Keep` — оставить локальные файлы; dialog предупреждает о возможных конфликтах при смене client spec.

**Depot/workspace content после switch**

- `Download now` — после смены stream выполнить preview sync и затем sync всего нового mapped workspace scope;
- `Keep as is` — изменить stream в client spec без немедленного sync.

Безопасный порядок операции:

1. Перечитать текущий workspace и opened changes.
2. При стратегии Shelve выполнить server shelf и остановиться при ошибке.
3. Получить актуальную client spec, заменить только `Stream`, сохранив неизвестные поля/options.
4. Перечитать workspace/server info.
5. При Download now запустить существующий sync operation protocol.
6. Показать частичный результат честно: смена spec могла пройти, даже если sync не удался или был отменён.

Dialog запрещает повторный submit, имеет безопасный default и не использует browser `confirm`.

## 6. Локализация и доступность

- Все новые строки добавляются одновременно в полные `locales/en.json` и `locales/ru.json`.
- Sidebar, tree, graph, context menus, source switcher, disclosure controls и dialog доступны с клавиатуры.
- Context menu открывается по ПКМ, `ContextMenu` и `Shift+F10`.
- Hover-only информация дублируется через focus/title/inspector.
- Проверяются RU/EN, длинные пути и названия, узкое окно, scale 100/125/200% и `prefers-reduced-motion`.

## 7. Проверки и границы

- Pure frontend tests: три состояния sidebar, построение дерева, unactual partition/cleanup и stream graph/tree state.
- Rust tests: stream list parser, безопасные arguments, сохранение client form при смене Stream и ветвление switch workflow.
- Полный gate: frontend tests, Rust fmt/test/Clippy и release build.
- Mutating `p4` smoke на подключённом пользовательском сервере не выполняется без отдельного разрешения.
- Функции, для которых сервер не отдаёт надёжные данные (например, размер локального untracked файла вне безопасного backend scope), показывают отсутствие значения, а не выдумывают его.

## 8. Критерии готовности

- [x] Sidebar по умолчанию компактный, раскрывается и скрывается; навигация соответствует новой группировке.

- [x] Local Files при входе показывает весь mapped workspace; дополнительные scope/search/filter controls не заслоняют дерево.

- [x] Игнорируемые элементы оформлены приглушённым оранжевым; local-only в depot mode серые и неактивные.
- [x] My Changes имеет рабочую persistent Unactual section без изменения server state.
- [x] My Changes переносит numbered changelist в/из Unactual через context menu и DnD.
- [x] Streams загружается с сервера, строит дерево/граф, поддерживает multi-select, batch visibility и сворачиваемые ветки, имеет persistent Unactual section с DnD и безопасный switch dialog.
- [x] Все mutations используют узкие Tauri commands, validation, direct `Command` arguments и refresh.
- [x] EN/RU packs полны, тесты и release build проходят.

## 9. Уточнения после повторной UX-проверки

- Drop-target Unactual занимает всю оставшуюся нижнюю область колонки My Changes и Streams, поэтому подсветка не обрывается на последней строке списка.
- Local Files публикует filesystem scan порциями и не блокируется автоматическим reconcile-preview; серверные статусы остаются read-only и приходят позже.
- Выключение checkbox внутри multi-selection скрывает все выбранные ветки одним действием.
- Включение родителя не меняет детей; выключение родителя каскадирует вниз.
- В context menu stream доступны отдельные `Показать все дочерние` / `Скрыть все дочерние` и эквивалентные команды Unactual.
- Узлы графа не масштабируются выше фиксированного layout-размера; текущий stream имеет самостоятельный цветовой акцент.
